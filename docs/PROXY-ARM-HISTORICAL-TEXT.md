# 历史文本代理臂：结果与为何它不能充当纯人类对照组

**日期**：2026-10-04
**臂名**：`human_poem`
**语料**：31 首唐代绝句（公有领域）
**状态**：⚠️ **代理臂，不是有效对照**

---

## 一、做了什么

为验证"增加一个语料臂"在工程上是否可行，并以历史文本作为纯人类对照的**代理**，
整理 31 首唐代五言/七言绝句，置于 `data/human_poem/`（与既有各臂同构：31 个 `.txt`）。

随后**以一致配置重算全部 7 个臂**（`--innov --target centroid`），
以免跨配置比较。

```bash
python scripts/pacsp_build.py --innov --target centroid \
       --datasets human_poem poem lyrics techdoc \
                  machine_poem machine_lyrics machine_techdoc \
       --out records_centroid/
```

## 二、工程可行性：✅ 成立

流水线**无需任何修改**即可处理新臂：

- 六层防护全部 `ok`
- 产出 `human_poem_epoch1_base_CT11.54Se_20261004.pacsp`
- 语料格式要求仅是"每目录 31 个 `.txt`"

**这是本次验证的主要结论**：加入新对照臂的门槛是**采集语料**，不是改代码。

## 三、实测结果

| 臂 | C_T (Se) | 篇均字节 |
|---|---|---|
| **human_poem（唐绝句，代理）** | **11.5368** | **72** |
| poem（人机交互） | 1.8950 | 112 |
| lyrics（人机交互） | 2.1261 | 1,196 |
| techdoc（人机交互） | 7.3982 | 19,545 |
| machine_poem（自主生成） | 3.8271 | — |
| machine_lyrics（自主生成） | 5.9210 | — |
| machine_techdoc（自主生成） | 2.4662 | — |

**同域两臂之比**：

| 域 | 人机交互 | 自主生成 | 自主/人机 |
|---|---|---|---|
| 诗歌 | 1.8950 | 3.8271 | **2.02** |
| 歌词 | 2.1261 | 5.9210 | **2.78** |
| 技术文档 | 7.3982 | 2.4662 | **0.33** |

前两域同向（自主组更高），技术文档反向——**与论文 §10.5 已记录的"无一致方向"一致**。

## 四、关键发现：这个代理**失败**了，且失败方式有信息量

**唐诗是全部语料中最短的（72 字节/首），却得到最高的 C_T（11.54）**——甚至高于
篇均 19,545 字节的技术文档（7.40）。

### 为什么

C_T 的实现是：

```
delta_k = ‖emb[k+1] − emb[k]‖₂                     # 相邻嵌入的欧氏距离（未归一化）
mu_k    = 滑动窗口内 (1 − cos_sim) 的均值            # 局部语义粗糙度
C_T     = Σ mu_k · delta_k
```

`μ_k` 含 **`(1 − cos_sim)`** 项。唐代文本相对 `bge-large-zh-v1.5` 的语义空间
**整体离群**——它的相邻快照之间方向差异大，故 `μ_k` 高；`delta_k` 亦大。

〔整理者按〕**因此 C_T 在跨语域比较时，很大程度上测的是"文本相对嵌入质心的语义距离"，
而不是"认知挣扎的深度"。** 这一条对论文本身也重要：`C_T` 的跨域数值
（1.9 → 7.4）可能有一部分来自语域距离而非认知负荷。§5.3 所称"μ_k 随认知负荷
严格递增"在**同一嵌入空间内的跨语域**比较中未必成立。

### 两个额外的混淆

1. **均匀性**：31 首绝句每首都恰好 72 字节，而 `poem` 臂为 36–150 字节。
   方差结构完全不同，这本身会影响 `delta_k` 的分布。
2. **同时变化的多个因素**：时代（唐 vs 2026）、语域（文言 vs 现代汉语）、
   正字法、采集方式、作者数（31 位唐代诗人 vs 同一批当代参与者）
   —— 全部与"是否有 AI 参与"同时改变。

## 五、因此它能支持与不能支持的结论

**能支持**：

- 流水线可无改动接纳新对照臂 ✅
- 域间差异（6.09×）**远大于**轴间差异（0.33–2.78×）
- C_T 对嵌入空间中的语义离群高度敏感——这是一个**测量效度警告**

**不能支持**：

- ❌ 任何关于"纯人类 vs AI"的判定
- ❌ 任何对 §8.5 判定表的补充
- ❌ 任何"人类认知沉积更高/更低"的推论

**唐绝句的高 C_T 不能被解读为"人类挣扎更深"**——它更可能只是"文言文离现代中文
嵌入质心更远"。

## 六、真正需要的对照设计

| 方案 | 做法 | 可支持的结论 |
|---|---|---|
| **B · 当代人类采集** | 真人按同一题域写作，**明确禁用 AI**；同一采集期、同一平台 | 时代与语域对齐，可支持"人类独写 vs 人机协作" |
| **C · 同源三臂** | 同一组人、同一题域，分别产出：人类独写 / 人机协作 / AI 独写 | **唯一能干净分离"是否有人筛选"的设计** |

**B 与 C 都必须新采集语料。** 本代理臂已证明采集完成后可直接投入流水线，
无需改动代码。

## 七、复现

```bash
python scripts/pacsp_build.py --innov --target centroid --datasets human_poem \
       --out records_centroid/
python scripts/pacsp_figure.py --records records_centroid --out cache/figures_centroid
```

`data/human_poem/_PROVENANCE.json` 记录了本臂的来源、选用理由与上述局限，
随语料一同存放，以免后人误用。
