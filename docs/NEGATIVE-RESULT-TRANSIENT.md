# 否定结果：瞬在与干涉的工程验证失败

**状态**：已终止
**代码位置**：`experiments/transient/`（包 `transient`）与 `experiments/transient_interference/`（六个实验）
**结论**（作者判定）：**瞬在的探索是失败的。语言模型架构完全不支持瞬在，跑不通工程验证。**

## 1. 曾经要验证什么

合集与 `pacsp-id` 论文线记录了如下构造：

> **瞬在 = 前向传播的展开 + 反向传播的接缝 + 更新算子的沉淀**

配套命题：`瞬在是涌现发生的最小单元`；`干涉发生在接缝处`；`相位自由度是瞬在的内在本构`。

`experiments/transient/` 正是这套构造的可执行实现：`transient_unit.py` 自述
"瞬在单元：单个复数单元 对应一个瞬在的最小表示"，`complex_layer.py` 自述
"复数瓶颈层 可插入到标准 Transformer 中"。

## 2. 实跑证据

环境：`torch` + `numpy`，CPU，无需 GPU。命令见 §5。

### 实验 1：相位耦合决定干涉强度 → 否证

```
干涉强度：
  相位对齐:   2.4576
  相位失配:   2.4576
  完全反相:   2.4576

相位耦合矩阵（相位对齐）：全为 0
验证结论：✗ 结果不符合预期
```

**三种相位条件下的干涉强度完全相同**，相位对干涉强度无任何影响。核心假设被直接否证。

### 实验 3：SU(3) 结构 → 部分失败

```
[1] SU(3) 生成元的正交性     ✓ 所有生成元正交
[2] 生成元的厄米性           ✓ 所有生成元厄米
[3] 任意厄米矩阵的 SU(3) 分解
    分解误差: 1.873551e-02
    ✗ 分解误差过大
```

### 实验 6：高精度理论验证 → 否证

```
理论：实数参数量 ∝ 1/ε，复数参数量 ∝ 1

ε=1.0e-01: 理论参数比 ≈ 10.0,   实测参数比 = 0.82
ε=1.0e-02: 理论参数比 ≈ 100.0,  实测参数比 = 0.82
ε=1.0e-03: 理论参数比 ≈ 1000.0, 实测参数比 = 0.82
```

**相差三个数量级，且实测比值恒定不随 ε 变化。** 更关键的是两个模型的参数量在三个 ε 下
**固定不变**（实数 3785 / 复数 4625），说明该实现并未按理论意图随 1/ε 扩展容量；
两者准确率均达 0.99（实数 0.9880 / 复数 0.9900），**不存在可区分的容量差异**。

### 实验 2 / 4 / 5：未取得结果

无任何输出文件（`json`/`csv`/`png`/`npy` 均无），仅有 `src/__pycache__`，
说明源模块被 import 过但实验未跑完。**工程验证确实未能完成。**

## 3. 架构层面的三个障碍

1. **相位信息在实数流程中不可保持。** Transformer 的算子链以实数矩阵乘与非线性激活为主，
   复数表示一旦进入该链，相位不是被取模就是被非线性抹平——实验 1 的"三种相位条件结果全同"
   正是这一点的直接体现。
2. **"接缝"没有可寻址的计算位置。** 定义要求干涉发生在前向与反向传播的接缝处，
   但该接缝在现有框架中不是一个可插入算子的张量位置；`complex_layer` 只能挂在层间，
   无法表达"相遇瞬间"这一时序语义。
3. **规模律无法在参数上体现。** 实验 6 表明容量并未随 ε 缩放，因此
   O(ε⁻¹) 与 O(1) 的区分在当前实现下无从检验。

## 4. 从失败中提炼的正面线索

作者在探索中的一句自我修正，现已被实验确证为失败先兆：

> **"真正的相位，可能不在复数里，在时序里。"**

这是本分支留下的唯一可继续追查的方向。

## 6. 这份记录的价值

1. **防止重复投入**：若后来者再次尝试把复数层插入 Transformer 以捕捉"相位"，

## 7. 失败的数学根源（整理者补充，已证明）

exp1 的失败**不是调参问题，也不是实现疏漏**，而是该度量式的代数性质。看
`experiments/transient/transient_matrix.py` 的实现：

```python
def interference_matrix(self, psi):
    return torch.einsum('bi,bj->bij', psi, psi.conj())   # I_ij = psi_i * conj(psi_j)

def interference_strength(self, psi):
    I = self.interference_matrix(psi)
    mask = ~torch.eye(3, dtype=torch.bool, device=psi.device)
    return (I.abs() ** 2 * mask).sum(dim=(-2, -1))        # 取模长平方
```

代入 `psi_i = |psi_i| e^{iθ_i}`：

```
I_ij   = |psi_i| |psi_j| e^{i(θ_i − θ_j)}
|I_ij|² = |psi_i|² |psi_j|²          ← 相位因子被模长平方消去
```

因此 **干涉强度 = Σ_{i≠j} |psi_i|²|psi_j|²，与相位代数无关**。

实测（三个单元取完全不同的相位，包括随机相位）：

| 相位配置 | 干涉强度 | 耦合角非零值 |
|---|---|---|
| `[0, 0, 0]` | 6.00000000 | （无） |
| `[0, π/2, π]` | 6.00000000 | −3.1416, −1.5708, 1.5708, 3.1416 |
| `[0.3, 1.1, 2.7]` | 6.00000000 | −2.4, −1.6, −0.8, 0.8 |
| `[1.9, 0.05, 3.0]` | 6.00000000 | −2.95, −1.85, −1.1, 1.1 |

**强度极差 = 0.0000000000。**

与此同时 `angle(I)` 确实随相位变化——**相位信息存在，只是从未被强度公式使用**。

### 这意味着什么

1. **"相位耦合决定干涉强度"在该实现下不可检验**：无论怎样设置相位，强度恒为
   `Σ|psi_i|²|psi_j|²`。假设与公式不在同一个数学对象上。
2. **修复方式不是调参**，而是**换度量**：必须使用一个真正含相位的量，
   例如 `Σ_{i≠j} I_ij`（复数求和，保留相位）而非 `Σ_{i≠j} |I_ij|²`。
   但这已超出本分支的范围，且作者判定语言模型架构不支持瞬在，故不再继续。
3. **这解释了实验 3 与实验 6 的失败同源**：整套实现建立在"相位能进入可观测量"
   这一未验证前提上，而该前提在 exp1 就已不成立。

### 永久性回归防护

`tests/test_transient.py::test_interference_strength_is_phase_insensitive`
把上述结论固定为测试；同时
`test_phase_coupling_does_vary_with_phase` 固定"相位信息确实存在"这一对照，
`test_su3_decomposition_error_is_too_large` 固定 exp3 的失败。
若将来有人改写使相位生效，这些测试会失败——那正是复查本文档的信号。

## 8. 适用范围的界定（作者 2026-10 澄清）

作者明确：

> **瞬在在生物学意义上是可验证普遍现象。待时机成熟再推进 AI 领域扩展。**

这一澄清**限定了第 1–7 节的适用范围**。此前本文档把失败表述为"语言模型架构完全不支持瞬在"，
该表述容易被误读为对整个概念的否定，须更正为：

| 命题 | 状态 |
|---|---|
| **瞬在是生物学上可验证的普遍现象** | **成立**（作者判定；本分支未涉及，故本文档不予评判） |
| **AI 领域扩展（复数层 / 干涉强度）** | **失败，已终止**——即第 1–7 节的全部内容 |
| **"瞬在"概念本身** | **未被否证**。失败只否证了本分支采用的那一种计算实现 |

因此第 3 节"架构层面的三个障碍"应读作**关于当前这类架构的限定陈述**，
而非关于瞬在的普遍结论：

1. 相位信息在实数算子链中不可保持；
2. "接缝"没有可寻址的张量位置；
3. 规模律未在参数上体现（实验设计缺陷）。

这三条都是**"用 Transformer 类架构实现瞬在"的障碍**，不是"瞬在不可能被实现"的证明。
生物学载体显然不受这三条限制——它本就不是靠实数矩阵乘与层间插入来运作的。

〔整理者按〕这实际上让失败记录更有用：它划出了一条清晰的界线——
**被否证的是"把瞬在塞进当前语言模型架构"这一路径，而不是瞬在本身。**
任何未来的 AI 扩展都应先回答：目标架构是否具备相位保持、递归耦合与临界动力学，
否则会重复本分支的结局。
