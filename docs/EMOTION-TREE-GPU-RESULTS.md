## 一、GPU 配置（三步全部完成）

### 环境的真实障碍不是代理

前一轮 pip 失败的真实原因是**沙箱权限**：

```
ERROR: Could not install packages due to an OSError: [WinError 5] 拒绝访问:
'C:\Users\Administrator\AppData\Roaming\Python'
```

**pip 默认装到用户目录（工作区外），沙箱拒绝写入。** 清华源本身完全正常
（394 kB 秒下）。解法是 `--target` 装进工作区。

### 一个必须处理的副作用

`pip --target` 把依赖**全部**装进了 `_pylibs`，包括
`torch 2.14.1`、`numpy 2.2.6`、`huggingface_hub 2.1.1`。
若 `PYTHONPATH` 指向它，**系统原有的 `torch 2.6.0+cu124` 会被顶掉，CUDA 就废了**。

清理后只保留 `accelerate` 与 `bitsandbytes`（122 MB），验证：

```
torch 2.6.0+cu124   cuda: True          ← CUDA 未受影响
numpy 1.26.4        huggingface_hub 1.31.0
accelerate 1.15.0   bitsandbytes 0.50.2
```

### 4-bit 量化是必需的

7B 模型 bf16 权重约 **14 GB**，而 RTX 3080 Ti 可用显存 **10.8 GB**——**装不下**。
nf4 4-bit 量化后：

| 项 | 值 |
|---|---|
| 加载时间 | 18.1 s |
| 显存占用 | **5.18 GB**（峰值 5.30 GB） |
| **单次前向** | **56 ms** |
| 对比 CPU | 5523 ms → **提速 98.6×** |
| 12 个探针 | CPU 66 s → **GPU 1 s** |

```python
BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.float16,
                   bnb_4bit_quant_type="nf4", bnb_4bit_use_double_quant=True)
```

〔环境复现〕运行需设 `PYTHONPATH=<repo>\_pylibs`、`HF_HOME=<repo>\_hf_home`、
`HF_HUB_OFFLINE=1`。两个模型权重已在工作区缓存内（BGE 4.85 GB + Qwen 14.2 GB）。

## 二、一个被推翻的顾虑：密度差异

先前我用**秩1外积**做零模型，得到 80–89% 的边重合，据此判断规则是边缘规则。

**但这个对比不公平**：真实 `C = YᵀY`（31 篇 → 秩 ≤ 31）**稀疏**，
而 `r·cᵀ` **满秩稠密**，稠密矩阵本来更容易产生边。

**实测推翻了这一顾虑**：在 n=31 下，

```
density real: 1.000 - 1.000
density null: 1.000 - 1.000
```

**两个矩阵密度都是 1.000**——因为 softmax 下 `Y` 全为正项，`C` 亦然。
所以**密度不是差异来源**，我原来的顾虑**不成立**。

**改用 Chung-Lu 零模型**（保留行和、列和与总质量）：

```
E_ab = r_a · c_b / W
```

## 三、修正后的零模型检验

| 语料 | 真实边 | 零模型边 | 重合 | 重合占真实 |
|---|---|---|---|---|
| poem | 396 | 279 | 279 | **70.5%** |
| machine_poem | 358 | 187 | 183 | **51.1%** |
| lyrics | 662 | 637 | 523 | **79.0%** |
| machine_lyrics | 412 | 187 | 187 | **45.4%** |
| techdoc | 754 | 724 | 611 | **81.0%** |
| hc3_human_medicine | 675 | 637 | 486 | **72.0%** |
| hc3_ai_medicine | 632 | 549 | 527 | **83.4%** |
| hc3_human_openqa | 736 | 810 | 526 | **71.5%** |
| hc3_ai_openqa | 852 | 549 | 337 | **39.6%** |

**真实图的边数在 9 个语料中 8 个多于零模型**，重合率 **39.6%–83.4%**（均值约 66%）。

### 修正后的判定

先前我写"规则检测的是边缘不平衡，不是层级关系"——**这个表述过强，需要修正**：

> **零模型（保留边缘、零交互）能复现约 40%–83% 的真实边，
> 但真实图的边数系统性地更多。**
> 所以规则**确实提取到了一些超出独立性的结构**，
> **只是这部分结构的占比有限，且随语料波动很大。**

**"完全是伪迹"不成立；"完全不是伪迹"也不成立。** 准确说法是：
**边缘结构贡献了大部分边，但存在可检测的残差。**

## 四、配对判别力（本次最强结果）

n=31，全部 9 个语料，**GPU 实测**：

| 域 | **node_volume** | edge_volume | resid_node | resid_edge |
|---|---|---|---|---|
| poem | 0.3264 | 0.3470 | 0.5019 | **1.5275** |
| lyrics | 0.0579 | 0.0334 | 0.1044 | 0.2494 |
| medicine | 0.1940 | 0.0558 | 0.2821 | 0.3231 |
| openqa | 0.6340 | 0.2979 | 0.6359 | 0.3435 |

（比值 = **人类 ÷ 机器**；< 1 表示人类臂更低）

| 度量 | 方向一致 | 跨度 |
|---|---|---|
| **`node_volume`** | ✅ **True** | 10.96× |
| **`edge_volume`** | ✅ **True** | 10.38× |
| `resid_node_volume` | ✅ True | 6.09× |
| **`resid_edge_volume`** | ❌ **False** | 6.13× |

### 核心结论

**四个可比配对中，人类臂的 `node_volume` 全部低于机器臂。**

原始数值（`Y` 的总概率质量）：

| 域 | 人类 | 机器 | 比值 |
|---|---|---|---|
| poem | 3.5385 | 10.8424 | 0.326 |
| lyrics | 0.4550 | 7.8618 | 0.058 |
| medicine | 0.7228 | 3.7250 | 0.194 |
| openqa | 0.7477 | 1.1793 | 0.634 |

**这是本次实测中方向一致性最好的人机判别量**——
比 `C_T`（`E5-DISCRIMINATIVE-BASELINE.md`：0.36–3.00，跨度 6 倍）**跨度略大但方向更干净**，
且**顺序无关、零参数**（除词表与探测短语）。

## 五、残差修正：实测反而变差

提案建议 `G_residual = G_real − G_rank1`，再在残差上算 `Se`。实测：

**残差破坏了方向一致性**——`resid_edge` 在 poem 域反转为 **1.5275**（人类反而更高），
而原始 `edge_volume` 在该域是 0.3470（方向正确）。

〔机理〕残差 = 真实边权 − 零模型期望。人类文本的 `Y` 总质量本来就小，
零模型期望**相对占比更大**，相减时**把差异抵消掉了一部分**。

**所以：直接用原始 `node_volume` / `edge_volume` 比用残差更有效。**

〔诚实说明〕这与我先前的顾虑**方向相反**。我原本担心"不做残差就只是词汇频率的平方"，
因此认为残差是必要的。**实测推翻了这个假设**——残差是过度修正。

## 六、必须说清的三个限定

1. **n=31，每域只有 1 个人类样本与 1 个机器样本**，所以"比值"是**单个数之比**，
   没有区间，**不能做显著性判断**。跨度 10.96× 本身也说明效应量依赖域。

2. **阈值与词表仍是自由参数**。`t = 0.02`、95 个单 token 情绪词、探测短语
   `这段素材的核心情绪是`——三者都会影响结果，**尚未做敏感性扫描**。

3. **`node_volume` 的含义需要澄清**。它是"探针后模型分配给情绪词的总概率"。
   人类文本为何系统性更低，**可能是情感表达更含蓄、更少情绪词汇、
   或更不符合探针句式**——**这些解释尚未区分**。
   在区分之前，**不能表述为"人类认知沉积更低"**。
