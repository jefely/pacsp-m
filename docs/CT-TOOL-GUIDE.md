# C_T 测量工具：用法与读数须知

`scripts/pacsp_ct.py` 是一个小工具：给一个（或多个）纯文本目录，直接算出 C_T。
它**调用与流水线同一组函数**（从 `pacsp_build` 导入），所以数值与
`pacsp_build.py` 产出完全一致——不是另写一套公式。

---

## 一、为什么写这个工具

原先要测一个语料的 C_T，得跑完整的六层构建、再读 record 文件。本工具把这一步压成一条命令。

```bash
cd PACSP-ID

# 单个语料
python scripts/pacsp_ct.py data/poem

# 多语料对比
python scripts/pacsp_ct.py data/poem data/machine_poem data/techdoc

# 带 95% 区间（块自助法）
python scripts/pacsp_ct.py data/poem --bootstrap 2000

# 输出 JSON 供后续处理
python scripts/pacsp_ct.py data/poem --json out.json

# 打印"这个数该怎么读"
python scripts/pacsp_ct.py x --explain
```

**输入约定**：目录下每个 `.txt` 是**一个快照**，按文件名排序后相邻两两计算。
快照是什么由使用者决定——本项目里"一篇文本 = 一个快照"。

## 二、它算什么

```
delta_k = ||emb[k+1] - emb[k]||           相邻快照嵌入的欧氏距离（未归一化）
mu_k    = 1 - 均值(窗口内余弦相似度)        局部语义"粗糙度"
C_T     = sum_k  mu_k * delta_k
```

嵌入模型默认 `BAAI/bge-large-zh-v1.5`（`--model` 可换），窗口半径默认 5（`--window` 可调）。

## 三、输出字段

| 字段 | 含义 |
|---|---|
| `C_T_Se` | 认知沉积量，单位瑟 |
| `delta_mean` / `delta_std` | 相邻位移的均值与标准差 |
| `mu_mean` / `mu_std` | 语义粗糙度的均值与标准差 |
| `bytes_mean` / `min` / `max` | 篇幅分布——**跨语料比较前必看** |
| `C_T_ci95` | 块自助法 95% 区间（`--bootstrap` 时给出） |

## 四、读数须知（四类已实测的混淆）

### 1. 长度效应

`delta_k` **未归一化**，文本越长可累积的位移越多，C_T 通常越大。
工具在对比末尾会自动检查：均长差异 > 10% 时打印警告。

### 2. 语域／离群效应

`mu_k` 含 `(1 - cos_sim)`。文本若整体远离嵌入空间中心，`mu_k` 系统性偏高。

**本项目实测**：唐代绝句（每首 72 字节，**最短**）C_T = **11.54 Se**，
高于篇均 19,545 字节的技术文档（7.40 Se）。当时一度误以为是"人类挣扎更深"，
实为文言文离现代中文嵌入质心更远。

### 3. 结构效应

相同字符数下，句子更短更密 → 更多语义跳变 → C_T 更高。

**本项目实测**（HC3 数据，长度已匹配）：
AI 答案的句数是人类的 **1.19–1.35 倍**，句均长 **0.60–0.64 倍**。

### 4. 模型效应

同一题、同一提示，**仅换生成模型**：

```
qwen2.5:7b        C_T = 9.5902
deepseek-r1:14b   C_T = 6.6421        相差 31%
```

## 五、一个重要的统计提醒

C_T 的点估计在**小语料上并不精确**。同一批语料（n=31）的块自助法 95% 区间：

| 语料 | C_T | 95% CI | 区间宽度 |
|---|---|---|---|
| `data/poem` | 1.8950 | **[0.9204, 3.2612]** | **3.5 倍** |
| `data/machine_poem` | 3.8271 | [3.5765, 4.1720] | 1.2 倍 |
| `data/techdoc` | 7.3982 | [6.0812, 9.0172] | 1.5 倍 |

**`poem` 的区间跨 0.92–3.26。** 因此：

- **报告 C_T 时应同时给出区间**，尤其在 n 较小时
- 两条语料的 C_T 差若**小于区间宽度**，不应断言有差异
- 区间宽度的差异本身也有信息：`poem` 的 `mu` 与 `delta` 变异更大（见 `--json` 的 `_std` 字段）

〔整理者按〕本项目此前多处比较 C_T（如 §10.2 的三域对比）都只给点估计。
**建议在论文中补上区间**，否则 1.90 与 2.13 这类接近的数值容易被当作真实差异。

## 六、什么时候可以比较，什么时候不可以

| 情形 | 可否比较 |
|---|---|
| 同一语料、同一模型、同一采集方式内部 | ✅ 有意义 |
| 长度匹配（±10%）、语域相近、结构相近 | ✅ 谨慎可比 |
| 长度差异大 | ❌ 测到的是长度 |
| 语域差异大（文言 vs 现代白话） | ❌ 测到的是离群度 |
| 生成模型不同 | ❌ 测到的是模型风格 |
| n 很小且未给区间 | ⚠️ 结论不稳 |

## 七、已知的实现细节

| 项 | 值 |
|---|---|
| 排序 | 按文件名（所以用 `001.txt` 这类零填充命名） |
| 窗口 | 边界处窗口自动收缩（首尾快照的 `mu` 基于更少的配对） |
| 归一化 | **不做**——`delta` 用原始欧氏距离，`mu` 内部用余弦 |
| 编码 | 文件按 UTF-8 读取 |
| 一致性 | 与 `pacsp_build.py` 共用函数，数值逐位相同 |

**一致性验证**：`data/poem` 经本工具得 `1.895004`，
经 `pacsp_build.py` 得 `1.895004`；`data/lyrics` 两处均为 `2.126140`。

## 八、复现

```bash
python scripts/pacsp_ct.py data/poem data/machine_poem --bootstrap 1500 \
       --json records_centroid/ct_demo.json
```

首次运行会加载嵌入模型（本机约 18 秒），之后同一进程内复用。
