在现代软件开发中，项目规模和复杂性日益增加，团队协作需求愈发强烈，因此工程化工具如虚拟环境、依赖管理变得尤为重要。上一节我们讨论了 Python 工程化的基本概念及其重要性；本节我们将深入探讨容器技术如何为开发者提供更为强大的隔离性和复现能力。

### 容器概述

容器是一种轻量级的、便携式的软件打包方式，它通过将应用程序与其依赖项一起封装在单一的、可移植的单元中来实现资源分离。这使得不同的开发环境可以在一个标准的基础上运行，确保代码的一致性，并且避免了传统虚拟机带来的性能开销和复杂配置。

### Python 与容器

Python 社区广泛支持 Docker 和 Podman 等容器技术解决方案。通过这些工具，我们可以为我们的项目创建自定义的镜像，在其中安装所需的依赖项、环境变量以及任何必要的配置文件。这使得开发者能够在不同环境下（开发、测试、生产）使用完全一致的工作流。

### 创建 Python 容器

首先需要准备一个 Dockerfile 或 Podman 的 `.podspec` 文件来描述运行项目的容器应该如何构建。例如，下面是一个简单的 Dockerfile 示例：

```docker
# 使用官方的 Python 3.9 镜像作为基础镜像。
FROM python:3.9-slim

# 设置工作目录并复制代码文件到容器内指定路径。
WORKDIR /app

COPY . .

# 安装项目的依赖项（此处假设使用 pipenv）。
RUN pip install --no-cache-dir -r requirements.txt

# 暴露应用程序的端口。
EXPOSE 5000

# 运行应用代码。假设计算机上运行的应用是 app.py 文件中的 Flask 应用。
CMD ["python", "app.py"]
```

上面提到，`requirements.txt` 和 `Pipfile`/`Pipfile.lock` 都是用来定义 Python 项目依赖的文件格式。使用这些工具可以确保在容器中安装了所有必要的库版本。

### 使用 Docker Compose

对于多服务应用来说，Docker Compose 是一个强大的工具用来管理一组相关联的应用程序部署方式。借助它我们能够轻松配置并启动多个容器化微服务，并且还能定义它们之间的网络连接与依赖关系。

例如创建一个 `docker-compose.yml` 文件：

```yaml
version: '3.8'
services:
  web:
    build: .
    command: python app.py
    ports:
      - "5000:5000"
    depends_on:
      - db

  db:
    image: postgres:latest
```

这段配置定义了一个基于当前目录构建的 `web` 容器，它会运行应用程序并将端口映射到主机上。同时指定了数据库服务使用官方 PostgreSQL 镜像。
